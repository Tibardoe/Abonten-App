## 2026-09-18 — Verification pass on the audit: one regression found and fixed, redelivery proven

- **Regression fixed — the message action overlay froze the keyboard value.** `ContextualActionOverlay` was still an RN `Modal`. - **Dead export removed**: `useKeyboardVisible` had no consumers after the audit.
- **Redelivery proven below the HTTP layer**: new integration suite `webhook-redelivery.integration.test.ts` (4 tests) runs `finalizePaystackPayment` against the replayed database with only Paystack's HTTP mocked — two concurrent deliveries of one `charge.success`, a fulfilment failure then a redelivery, a verify outage then a redelivery, and a direct second call of `issue_tickets_for_checkout` on a paid session. ## 2026-09-18 — Holistic engineering audit: keyboard architecture, webhook acknowledgement, database indexes

- **Fix — Paystack webhook only acknowledges settled outcomes.** `POST /api/paystack/webhook` answered 200 for every `charge.success` once the signature checked out, so a transient failure inside `finalizePaystackPayment` (a verify time-out, a database hiccup between the lock and ticket issuance) left the attempt retryable but told Paystack never to retry; the customer had paid and nothing issued the ticket until they tapped "Check again". The handler now answers 503 for `pending`, `fulfillment_failed` and `already_processing` (Paystack redelivers with back-off; the finalize lock makes each redelivery idempotent) and 200 only for `succeeded`, `failed` and `not_found`. The refund and transfer branches answer 503 on a database error for the same reason. Table and rationale: `@abonten/services/payments/webhookAck.ts` (unit-tested). `finance/settlement-ledger-and-payouts.md` and `architecture/integrations.md` unchanged in substance; the behaviour is recorded in PROJECT.md §35.

## 2026-09-17 — Mobile bottom sheets moved out of RN Modal

- **Changed — `@abonten/ui-native` `<Sheet>` renders through a portal** (`@gorhom/portal`, pure JS, no native build) into the app's own view hierarchy instead of an RN `<Modal>`, with `<PortalProvider>` added to `apps/mobile/app/_layout.tsx` below the theme/i18n/session providers (a portal renders at the host's position, so anything above it is out of context for a sheet) and above the navigator (so a sheet covers the tab bar). A Modal is a separate native window, and that one fact disabled every platform mechanism a sheet needs: Android's `windowSoftInputMode=adjustResize`, iOS's `automaticallyAdjustKeyboardInsets`, the app-root `GestureHandlerRootView`, and Reanimated's `useAnimatedKeyboard` — which was measured on device returning a constant zero inside the Modal. All of it works again outside one.
- **Fix — the sheet no longer jumps or resizes when a field is focused.** It used to be lifted by `marginBottom` = keyboard height while its max/min height were re-derived from `windowHeight - keyboardHeight`, so it translated and changed detent at once (the location sheet's top edge jumped y=1140 → y=748 on a test device). A sheet now moves only when something at its bottom edge must stay usable — a footer's action, or the content of a sheet that hugs its content — and never re-derives its height from the keyboard. Measured after: the location sheet holds y=1140 through open, focus, typing and dismissal, while the country picker rises so its whole list clears the keys (it previously showed none of it).
- **Changed — keyboard motion runs on the UI thread** via `useAnimatedKeyboard`, the same approach the Spotlight comments panel and Story reply bar already use, replacing a JS-listener height with a timed animation chasing it.
- **Changed — Android back inside a sheet** dismisses the keyboard first and leaves the sheet open; a second back closes it (an explicit `BackHandler`, since `Modal.onRequestClose` is gone).
- **Changed — one reveal engine**: the "scroll the focused field above the keyboard" logic moved out of `KeyboardAwareScrollView.tsx` into `useKeyboardReveal.ts`, shared by the full-screen forms and `<Sheet>`, replacing the sheet's previous blind `scrollToEnd()`. The "Edit message" sheet's raw `TextInput` is now the shared `<Input>` so it reports focus and growth.
- **Note — `@gorhom/bottom-sheet` was evaluated and rejected**: its v5 is written for Reanimated 3 and does not work on Reanimated 4 / Expo SDK 57 (`present()` runs, no `onChange` fires, nothing renders — upstream issues #2546 / #2528 / #2592). Only its dependency-free portal package is used. `@expo/ui`'s BottomSheet was also rejected: on Android it is a Compose dialog, i.e. the same separate-window trap.
