# Limitations, risks and deferred items audit — 2026-09-26

Every item still open in [01-limitations-register.md](01-limitations-register.md),
[02-remediation-roadmap.md](02-remediation-roadmap.md) and reports 03–10 was
re-checked against the code and production, and production itself was
examined for things no register listed (runtime errors, job history, database
growth, media that no longer exists). Everything that could be fixed from the
repository was fixed and tested. What remains needs the founder's accounts or
decisions (§5).

## 1. Found in production that no register listed

| # | Finding | Evidence | Impact |
|---|---|---|---|
| P1 | **Expired event drafts destroyed live event flyers.** `cleanup_expired_drafts()` queued an expired draft's flyer for deletion without checking whether the published event used the same image, and the queue drain destroyed it unconditionally. | 14 of 23 distinct flyers referenced by production events return 404 from Cloudinary. 13 belong to events archived at 16:58 UTC on 2026-09-04 (the pre-fix expiry function deleted the flyer, then failed to delete the row — DATA-006). "The Dog" (created 2026-09-05) lost its flyer afterwards, which only the draft path explains. | Broken images on every card, ticket and receipt that shows those events. All 25 production events are past and archived, so no live listing is affected today; any future organizer publishing a draft without its id would have lost their flyer after 48 hours. |
| P2 | **Scheduled-job history grows without limit** on a database the free plan caps at 500 MB. | `cron.job_run_details`: 190,604 rows, 43 MB, oldest February 2025, about 7,000 rows a day. Database 208 MB. | Unbounded growth toward the plan limit. |
| P3 | **Scheduled-job failures were invisible.** Admin › Monitoring had no row for pg_cron itself. | Health keys in production: `auth, cloudinary, db, fieldops, hubtel, paystack, push, resend, rewards, self, storage, weekly` — none for jobs. The 2026-09-13 storage purge failed nightly for days before anyone saw its effect. | A failing job surfaces only through its consequences. |
| P4 | **Ticket email PDFs logged "Attempt to access memory outside buffer bounds"** twice per registration (report 09 §7, left open). | Reproduced: react-pdf prints exactly that when an image URL answers 404 with an empty body, and draws nothing. Logo, recent flyers and QR codes render cleanly. | Log noise; a ticket PDF without its flyer (P1) or, worse, without its QR code if that image were ever missing. |
| P5 | **The release smoke test filled the error log.** | 18 of the week's 26 web runtime errors were Resend refusing the smoke test's `@example.com` buyers. | Real errors after a deploy were buried among expected ones. |
| P6 | **Reward notices hard-coded cedis.** Seven reward functions built their text with a literal "GH₵" and `amount / 100.0`, which CLAUDE.md's global-platform rule forbids. | `pg_get_functiondef` of `_reward_accrue`, `_reward_friend_decide`, `_reward_loyalty_evaluate`, `referral_bind`, `rewards_notify_pending`, `rewards_run_monthly_rebates`, `rewards_settle_due`. | A reward in any other currency, or one with 0 or 3 decimals (yen, dinar), would be announced in the wrong money. Rewards run in shadow mode, so no notice has gone out wrong. |
| P7 | **"Happening today / this month" used the server's UTC clock** on the web (not in report 08's list of four). | `getEventsInWindow.ts` (date-fns `startOfDay` on the server) and three server-rendered slider call sites. | Wrong day for any visitor outside UTC+0 once another market opens. |
| P8 | **Two admin label mismatches.** The health keys `push` and `rewards` had labels filed under `expo` and `rewards_health`. | `statusLabels.ts` | Rows showed raw keys in Admin › Monitoring. |
| P9 | **Nine SQL functions converted money with a fixed `* 100`**, right only for two-decimal currencies. | Reward evaluators, `_reward_event_rebate_basis`, `_reward_commit_budget`, `content_campaign_activate_from_checkout`, `credit_reconciliation_checks`. Côte d'Ivoire (XOF, no decimals) is a configured draft market. | In XOF: every paid Spotlight campaign refused after payment, false credit-mismatch alarms, rewards 100× too large; and the reward budget added revenue across currencies. No effect in Ghana. |
| P10 | **Nobody was told when production was unhealthy.** Failed health checks and incidents appeared only on Admin › Monitoring. | Found after the deploy: the Abonten Weekly check had been red since 2026-09-21 08:58 UTC — the programme was switched on for everyone on 2026-09-18, and no Ghana edition exists for the week of 21 September (production has no upcoming events to feature). | A broken job, integration or programme could go unnoticed for days. |

What was done:

- **P1.** Expired drafts now queue a flyer only when no event, live draft,
  place, place draft or gallery photo uses it (migration
  `20260926100100`), and the queue drain re-checks the same references
  right before destroying (`cloudinaryCleanupCore`). The 14 lost files
  cannot be recovered, so every image URL now names a Cloudinary default
  image (`d_`): a missing flyer or photo shows a neutral branded
  placeholder (`branding/image-fallback`, uploaded 2026-09-26) and a missing
  avatar the default avatar. QR codes get no placeholder.
- **P2.** A `purge-cron-run-details` job keeps 14 days of job history.
- **P3.** `cron_health()` and a `cron` health key ("Scheduled jobs"): down
  when an active job's latest run failed or a run is stuck over 30 minutes.
- **P4.** The server-side ticket PDF fetches its images first, leaves out
  one that cannot be used, and redraws a missing QR from the ticket code.
- **P5.** Smoke-test accounts use Resend's `delivered+…@resend.dev` test
  inbox, and the smoke test picks the newest flyer.
- **P6.** `money_text(minor, currency)` formats every reward notice in the
  reward's own currency (migration `20260926100300`).
- **P7.** See the calendars row below.
- **P8.** Labels corrected; `cron` and `stripe` added.
- **P10.** A check failing 3 runs in a row opens an incident, and every new
  incident (from any source) is emailed once to the active super-admins
  from the Abonten Monitoring sender, production only (migration
  `20260926100600`, `incidentAlertsCore`). The first email to arrive will be
  the Weekly one; publishing an edition, or switching the audience back to
  staff until there are events to feature, is the founder's call.
- **P9.** `public.currency_scale(currency)` (10 ^ minor units) replaces
  every fixed `* 100`, keeping each floor and round as it was, so Ghana's
  amounts are unchanged to the pesewa (all 95 reward, credit and promotion
  integration tests pass unchanged); the reward budget counts only the
  default market's currency (migration `20260926100500`).

## 2. Fixed from the registers and earlier reports

| Item (source) | What was done |
|---|---|
| Four calendars count UTC days; readiness blocks every market outside UTC+0 (report 08 §9, 09 F6) | Organizer dashboard, event insights and transactions count "today" and "this month" in the **viewer's** zone (browser cookie `abn_tz`, or the phone's zone sent as `tz`, else the default market's); `get_organizer_sales_timeline` / `get_organizer_dashboard` take `p_timezone` and bucket by it. Promo codes end at midnight in the **event's** zone and are stored as the calendar day picked. The monthly rebate run counts each event in the month it settled in its own zone. The readiness `utc_calendar` check is removed. P7 fixed the same way. |
| Date-window feed evaluates every listing in the radius (reports 08, 09) | Earliest in-window start taken from two new start-time indexes; price and dates built only for the page. 378 → 62 ms at 50 km, 77 → 3.6 ms for "today" (§3). Results identical page by page. |
| iOS 3.1.1 / 3.1.3: boosts sold through Paystack (reports 08, 09 — blocking) | The iPhone app does not sell promotions or point elsewhere to buy them; existing promotions stay visible. One switch in `apps/mobile/src/lib/storePolicy.ts`. In-app purchase is decision D6. |
| iOS 4.8: Google sign-in without an equivalent (reports 08, 09 — blocking) | Sign in with Apple (native button, `supabase.auth.signInWithIdToken`), iOS only, shown only on builds that include the module. Founder steps in [../mobile/08-phase-6-release-prep.md](../mobile/08-phase-6-release-prep.md). |
| iOS privacy manifest relied on each pod (reports 08, 09) | App-level `ios.privacyManifests` declared (no tracking; user defaults, file timestamps, boot time, disk space). |
| Cron-failure health check (report 03 §5, "small follow-up") | New `cron` health key (P3). |
| `vitest` 3.2.7 path-traversal advisory (report 06 §8) | vitest 4.1.11 in `@abonten/core` and `@abonten/services`; all 908 unit tests pass unchanged. |
| Admin refund leaves the transactions list stale (register, cache sweep) | The action revalidates `/finance/transactions` too. |
| Seven trigger functions executable by `anon` / `authenticated` (advisor) | EXECUTE revoked; Postgres checks it only when a trigger is created, never when it fires. |
| Stale register entries: ARCH-001, ARCH-002, TYPE-001, MOB-001, SEC-001 tests, BIZ-001 free path | Re-verified and closed with dated notes in the register. |
